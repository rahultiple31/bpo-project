# Nexora CX BPO Website

Nexora CX is an original BPO and customer experience website starter inspired by common CX outsourcing patterns: AI-assisted support, omnichannel operations, BPaaS, consulting, digital capabilities, industry coverage, proof metrics, case studies, and contact conversion.

Reference reviewed: <https://isonxperiences.com/>

## What is included

- Static website source: `index.html`, `assets/css/styles.css`, `assets/js/main.js`
- nginx production runtime: `Dockerfile`, `nginx.conf`
- Raw Kubernetes manifests: `k8s/` using a NodePort service for local clusters
- Helm chart: `charts/nexora-cx/`
- GitHub Actions image build pipeline: `.github/workflows/ci-cd.yml`

## Run locally

Open `index.html` in a browser, or serve it with any static web server.

With Docker:

```bash
docker build -t nexora-cx:local .
docker run --rm -p 8080:8080 nexora-cx:local
```

Open <http://localhost:8080>.

## Push to GitHub

```bash
git init
git add .
git commit -m "Add Nexora CX BPO website and Kubernetes deployment"
git branch -M main
git remote add origin https://github.com/<your-org>/<your-repo>.git
git push -u origin main
```

The workflow publishes the image to:

```text
ghcr.io/<github-owner>/nexora-cx
```

## Deploy with raw Kubernetes manifests

Update `k8s/deployment.yaml`:

```yaml
image: ghcr.io/rahultiple31/nexora-cx:<tag>
```

Apply:

```bash
kubectl apply -f k8s/namespace.yaml
kubectl apply -f k8s/deployment.yaml
kubectl apply -f k8s/service.yaml
kubectl apply -f k8s/hpa.yaml
```

Check rollout:

```bash
kubectl rollout status deployment/nexora-cx -n nexora-cx
kubectl get pods,svc,hpa -n nexora-cx
```

Open the app through the NodePort service:

```text
http://<node-ip>:30080
```

## Deploy with Helm

Install or upgrade:

```bash
helm upgrade --install nexora-cx charts/nexora-cx \
  --namespace nexora-cx \
  --create-namespace \
  --set image.repository=ghcr.io/rahultiple31/nexora-cx \
  --set image.tag=<tag>
```

For local cluster testing with a local image:

```bash
helm upgrade --install nexora-cx charts/nexora-cx \
  --namespace nexora-cx \
  --create-namespace \
  --set image.repository=nexora-cx \
  --set image.tag=local \
  --set image.pullPolicy=Never
```

Open `http://<node-ip>:30080`.

## GitHub Actions and ArgoCD setup

The included workflow validates Helm, builds the Docker image, pushes it to GHCR, then updates `charts/nexora-cx/values.yaml` with the new immutable image tag on pushes to `main`.

Point ArgoCD at this repository and the `charts/nexora-cx` chart path. ArgoCD will deploy the chart from Git; the GitHub Actions workflow does not connect to the Kubernetes cluster directly.

In repository settings, make sure GitHub Actions has permission to write repository contents so it can commit the updated Helm image tag.

## Customize

- Change brand and page copy in `index.html`
- Update colors and layout in `assets/css/styles.css`
- Connect the contact form to a CRM/API in `assets/js/main.js`
- Change Helm defaults in `charts/nexora-cx/values.yaml`
- Change the NodePort in `charts/nexora-cx/values.yaml` if port `30080` is already used

## Production notes

- Ingress is not included because this chart is configured for local Kubernetes and ArgoCD sync through a NodePort service.
- Keep image tags immutable in production, for example the Git SHA tag generated by the workflow.
- The container listens on port `8080` and exposes `/healthz` for readiness and liveness probes.
- The nginx config includes basic security headers and cache headers for static assets.
